## Summary

approach review; review-derived changes are marked **[review]**.

## Feature 1: Config repair fixes (fix tier 2)

Crosses the v0.7.0 own-state line deliberately: the user config file is
edited, but only ever by commenting lines out — never deleted, never
rewritten wholesale.

Two registry entries (precise per-check attribution):

| Fix id | Source check | Tier | Action |
|---|---|---|---|
| `repair-config-lines` | `config-valid` | `config` | Comment out each line the loader flagged (malformed or unknown key), prefixing `# brew-usage-fix disabled line N: ` |
| `clamp-cache-ttl` | `ttl-sane` | `config` | When `CACHE_CLEANUP_DAYS>30`: comment the old line (`# brew-usage-fix clamped from N`) and write `CACHE_CLEANUP_DAYS=30` in its place |

Safety requirements:
- Timestamped backup (`cp -p file file.bak-YYYYmmddHHMMSS`) before the
  first edit of the apply pass; if the backup fails the fix reports
  failure and edits nothing. **[review]** Shared once-per-pass guard so
  two config fixes don't double-backup
- Atomic write: mktemp in the config file's directory + `mv`
- **[review]** After-report truthfulness (resolves the PRD-004 spec-review
  subshell note): config globals are loaded at startup, so after applying
  any `config`-tier fix the entry point re-runs `load_config_file()` before
  the after `doctor_run_all` — the loader is a pure re-read, and with bad
  lines commented it re-emits no warnings, so the after report shows the
  repaired state honestly. Apply functions stay subshell (file effects
  only); the tier field drives the re-source from the main shell
- `doctor_check_config_effective` unchanged (it already reads the globals
  the re-source refreshes)

## Feature 2: JSON fix plan (`doctor --fix --json`)

Lift the `--fix` × `--json` conflict; compose fully:

- `doctor --fix --json` — dry-run: existing `{checks, summary}` report
  plus a `"fixes"` array: `[{id, check, tier, description}]` (empty array
  when nothing fixable)
- `doctor --fix --yes --json` — apply, re-source config if a config-tier
  fix ran, re-run doctor, emit the after JSON with
  `"fixes": [{id, status: "applied"|"failed", result}]`
- **[review]** stdout purity: in JSON mode, all human-oriented lines
  ("Planned fixes…", "applied: …", count footers) are suppressed on
  stdout — they move to stderr or are dropped; stdout must always be
  valid JSON alone
- Assembly via `jq --arg` per key, consistent with `json_doctor_report`
- Exit codes unchanged (0/2/1 verdict semantics; invalid combos still 1)

## Feature 3: Version-specific size lookup (`--size name@version`)

**[review]** Formula-first, explicit-version fallback — deterministic and
backward compatible:

1. Try the argument as-is (`brew info --json=v2 name@ver`): today's path.
   Real versioned formulae (`go@1.21`) keep working exactly as now
2. If and only if that lookup fails **and** the argument contains `@`:
   split at the last `@`; the suffix must pass `is_valid_version` (else
   the existing invalid-name error); use the explicit version verbatim
   (user may pin revisions, e.g. `go@1.21.13_1`), skip version resolution,
   and fetch the `name--version--tag` manifest directly
3. No manifest for the pinned version → existing partial-failure path
   (warn, exit 2)

No new flags; `--quiet`/`--json` compose unchanged; cache filename uses
the explicit version (natural `name--version--tag` fit).

## Implementation findings (2026-08-20, Task 3)

- **ghcr hosts only each formula's current manifest tag** — historical
  version tags 404. A pinned version therefore resolves when it is the
  currently hosted version, or from Homebrew's local downloads cache when
  that version was ever fetched on this machine (the existing
  `*--name-version.bottle_manifest.json` path). A pinned version that is
  neither → the existing partial path: warn + per-package rc 2 (process
  exit 0 standalone / 2 in a mixed failing run, per PRD-002 semantics)
- Symlinked config files are refused by both config fixes (the atomic
  mv would replace the symlink itself and desync dotfile-manager setups)
- `go@1.21` no longer exists in homebrew/core (only 1.22+); the spec's
  examples were updated to use dynamically discovered live formulae so
  tests self-heal across releases
